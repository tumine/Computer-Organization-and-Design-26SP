### 课程回顾
**第 1 章**：了解计算机系统构成，熟悉计算机系统性能评估方法
- 性能评估方法：芯片成本计算、CPU 时间、Amdahl 定律（加速效果）
  - CPU 时间：程序执行的总周期数 $\text{CLK}$，计算机工作的时钟频率 $f$，$T_{\text{CPU}}=\frac{\text{CLK}}{f}$
  - **响应时间**：事件开始到结束的时间；用户标准
  - **吞吐率**：单位时间内能完成的工作量；多道程序系统视角
  - 性能比较：“X 比 Y 快”指的是 Y 的响应时间比 X 长（可以进一步量化），或者 X 的性能比 Y 好（性能与响应时间成反比）
  - 可靠性：平均无故障运行时间 **MTBF**
  - 可用率：平均修复时间 MTTR，可用率记为 **MTBF/(MTBF+MTTR)**
- 计算机的层次
  - 应用语言→高级语言→汇编语言→操作系统→机器语言→微指令系统
  - **每条机器码执行一个微程序**，每条微指令在一个时钟周期内指示某个功能部件完成一个原子硬件操作
  - 操作系统为汇编语言/高级语言提供其执行过程中使用的**基本操作的具体实现**，并管理计算机软硬件资源
- 计算机处理一条指令的过程

  - 如何串联各个组件？CPU、主存、磁盘、显示器
  - 冯·诺依曼架构的特点：五大功能组件，指令和信息如何表示，...
- CPU 发展趋势：核集成度→频率扩增→核扩增
  - CPU 发展过程中遇到哪些墙？处理和解决的思路是什么？
  - 存储墙与 I/O 墙：利用程序的时空局部性原理，引入存储器层次结构、访存 burst 技术、RAID 技术
  - 频率墙与线延迟墙：通过指令级并行增加在一个时钟周期内能完成的工作量，从而提高性能，引入流水线、超标量、超长指令字、乱序多发射等技术
- **Amdahl 定律**：加速的成本是什么？加速带来的效益是否足以覆盖成本？
  - 可改进比例 $f_e$，部件加速比 $S_e$，$S=\dfrac{1}{(1-f_e)+\frac{f_e}{S_e}}$
  - Amdahl 定律固定工作量来计算加速比，是一个悲观结果；Gustafson 定律提出固定并行计算时间来计算加速比，得到乐观结果
  - Gustafson 定律：性能与核心数成正比
- CPU 性能公式：$T_{\text{CPU}}=\text{CPI}\times \text{IC}\times T_{\text{CLK}}$，如何从三个参数入手分别进行优化？
  - 程序总指令数 $\text{IC}$，$\text{CPI}=\frac{\text{CLK}}{\text{IC}}$
  - 优化 IC：采用 CISC 指令集，针对特定计算系统的计算特性**引入专用指令**（如针对深度学习模型的计算需求，引入矩阵乘法指令）
  - 优化 CPI：采用流水线，超标量，超长指令字等技术，让整体 CPI 小于 1；采用多级缓存，减少访存指令的停顿数
  - 优化 $T_\text{CLK}$：加深流水线，采用 RISC 指令集（减少每个时钟周期做的工作量，从而能提高时钟频率）

**第 4 章**：设计并实现流水化的处理器（数据通路、控制信号、状态机），进行流水线性能评估，掌握各种相关的产生原因、解决方法（`260415.md`
- 流水线：在多周期的基础上，充分利用空闲的部件
- 流水线的性能评价：吞吐率、加速比、效率
  - 流水线不能缩短单个任务的执行时间，但可以提高吞吐率
  - 吞吐率 TP：单位时间内流水线完成任务的数量。在任务数极多的情况下，吞吐率趋近于流水线时间 $\Delta t_0$ 的倒数
    - 各个流水段时间不等时，理论最大吞吐率即为**最大流水段时间的倒数**
    - 计算实际任务完成时间，主要关注**每个任务流出流水线的时刻**；第一个任务走过完整的流水线，接下来每隔 $\Delta t_0$ 都会有一个任务流出
    - 流水段时间不等时，任务流入、流出的瓶颈都在于时间最长的流水段；可以画出一个实际例子辅助理解
  - 加速比 S：完成相同任务，非流水线执行与流水线执行的时间之比；**理论最大加速比即为流水段数量**（流水线稳定时，且假定各流水段用时相同）
  - 效率 E：实际加速比与最大加速比的比值，或执行完 n 个任务所需的**理想时间**（$n\cdot \Delta t_0$，因为流水线稳定后，每隔 $\Delta t_0$ 就会有一个任务完成）**与实际时间的比值**
    - 也可以理解为在时空图上执行 n 个任务占用的时空区域与相同时间内全部时空区域的面积比
    - 在 $\Delta t_0$ 不变的前提下，效率与吞吐率成正比
  - 提高吞吐率：细化流水段以压缩时钟周期，均衡流水段延迟，多发射流水线
  - 提高加速比：增加流水级数，引入分支预测，引入数据前递
  - 提高效率：增加任务数，采用非线性流水线，采用哈佛结构
- 结构相关：硬件资源不足
  - 通过引入**哈佛结构**来解决，指令和数据存储分离
- 为什么产生了数据相关？数据依赖
  - 旁路技术（判断、传送）
    - 分为 `EX/MEM → ID/EX` 前递、`MEM/WB → ID/EX` 前递
    - 对于 Load-Store 指令子序列，可以增加 `MEM/WB → EX/MEM` 前递路径来消除流水线停顿，但要考虑成本和性能权衡
  - 互锁（识别、停顿）
    - 读访存指令在 MEM 段结束后才拿到数据，下一条指令执行到 ID 段时发现数据相关，停顿一个时钟周期
    - 停顿的具体实现：当前时钟周期把下一个段（EX 段）的段间寄存器清零；**阻止 PC 自增和 IF/ID 段间写入**
- 控制相关：分支指令
  - 如何降低分支指令带来的开销：判断过程放到 `ID` 段，这一段实际执行的工作不多，有时序余量
    - 延迟分支：从前调度（从**分支指令之前**找一条不影响分支运行结果的指令，让它在分支指令之后运行）、从失败处调度、从目标处调度
    - 分支预测
      - 静态：认为向**后**转移 taken，向**前**转移 not taken；有利于循环执行过程中减少停顿
      - 动态：建立转移预测缓冲器，对每条分支指令根据其以前的跳转状态预测或更新状态位
      - 2 位动态预测器有两种实现方式，取决于切换预测结果时预测倾向是强（第一次预测错误时保持当前倾向不变）还是弱（第一次预测错误后立即切换预测倾向）
    - 不同的预测方法带来不同的预测精度
- 目标：让 CPI 尽可能靠近 1
- 让 $\text{CPI}<1$：超标量、超流水线、超长指令字
  - 额外的硬件资源需求
- 
- RISC-V 适于流水线的特点
  - 指令字定长
  - 每种指令的**操作数位置固定**，因此可以在 ID 段直接取操作数
  - **只有 Load/Store 访存**，这样不会出现“计算访存地址-访存-结果参与运算”这一个无法被其它类型指令复用的流水片段，缩减了流水线段数
  - 操作数在内存中**强制字对齐**，保证一次访存就可以取出操作数
- MIPS 与 RISC-V 数据通路的区别
  - 段间寄存器中和分支目标计算的基址是 PC（RISC-V）还是 PC+4（MIPS）
  - 源、目标寄存器编号的生成是否需要通过 MUX（这些寄存器在指令中的编码位置是否固定）
  - 立即数生成是否需要专用生成器
- 解决冒险的方法
  - 硬件：在指令运行时**动态**检测数据依赖
  - 软件：编译器运行时**静态**检测数据依赖；处理器之间的兼容性差

**第 5 章**：中断、异常本质上是 CPU 的功能扩展（`260506.md`、`260513.md`）
- 中断分类：软中断、硬中断
  - 软中断：由执行特定的指令触发，例如程序异常，断点；如果重新执行这个指令片段，**仍然会在相同的位置触发相同的中断**
  - 硬中断：与 CPU 当前执行的指令没有关系
    - 可屏蔽中断：一般的 I/O 设备发出的中断，可以不立刻处理
    - 不可屏蔽中断：发生严重硬件级错误时发出的中断，必须立刻处理
- 中断管理需要解决的问题
- 中断机构：软硬件协同逻辑
  - IF@PSW：位于程序状态字中，指示是否屏蔽外部所有可屏蔽中断；**架构特异性**
  - 中断请求标记 INTR：每个中断请求源对应一个 INTR 触发器
    - 分散布局：分布在各个中断源接口电路中
    - 集中布局：位于 CPU 中断系统内
  - INTA：CPU 响应中断的信号，用于冻结中断控制器状态，从中断控制器获取中断类型
  - 中断判优
    - 软件实现：通过一系列分支结构查询指令选定一个优先级最高的中断
    - 软件实现易于动态改变优先级，但中断判优过程开销较高
    - 硬件实现：链式排队器，关键在于**运用与非门**处理获得给下一个中断源的中断允许信号 INTP 输出
    - 排队器并行实现时判优效率高，串行实现时易扩展
  - 中断响应
    - 条件：CPU 允许中断触发器 EINT=1
    - 时机：在**单周期/多周期 CPU** 上，一条指令执行结束，CPU 发出中断查询信号
    - 中断隐指令：保护程序断点（PC 信息），寻找中断服务程序入口地址，禁用中断（不论是否允许嵌套中断，**至少在进入中断服务程序之前**）
  - 保护现场
    - 保存断点：由中断隐指令执行
    - 保存寄存器的值：由中断服务程序执行
    - 中断服务程序的结构：保护现场—执行真正的中断服务程序—恢复现场—中断返回
  - 寻找中断服务程序入口地址
    - 硬件向量法：由排队器选出优先级最高的中断，送入中断向量形成部件生成向量地址
    - 软件查询法：由 CPU 执行一系列中断查询指令找出优先级最高的中断，再执行查表指令找到该设备对应内存单元
    - 硬件向量法生成向量地址后，用该地址覆写 PC，下一步执行该地址上的 JMP 指令
    - 软件查询法先把内存单元上的地址数据加载到寄存器中，再执行一条间接跳转指令跳转到中断服务程序入口地址
    - 两种方法下内存单元中存储的内容完全可以互换，**并不与寻找入口地址的方法绑定**
  - 多重中断：允许中断打断中断
    - 提前设置开中断，在中断隐指令完成保存现场后、中断服务程序开始之前就打开中断
    - 优先级高的中断源可以打断优先级低的中断执行
    - 屏蔽：禁用低优先级的中断
    - 需要在硬件排队器的与非门上添加一个屏蔽位输入，所有屏蔽位组合形成屏蔽字，屏蔽字随着当前执行中断的优先级而不断动态改变
    - 新屏蔽字的设置需要在保存现场之后，以**保存原有屏蔽字和寄存器**，避免设置屏蔽字的过程覆写寄存器；老屏蔽字的恢复需要在恢复现场之后
    - 屏蔽可以改变处理优先级（软件逻辑，中断服务程序），但不能改变中断响应优先级（硬件逻辑，中断隐指令）
- 记录异常指令、异常信息：EPC 指向处理完异常后应当执行的**下一条正常指令**
- 算术溢出、异常指令的检测分别位于哪个周期？
  - 异常指令检测在 ID 段查出，在 EX 段开始执行异常处理
  - 算术溢出检测在 EX 段查出，在 MEM 段开始执行异常处理
- 
- 流水线异常处理
  - 非精确处理：允许已进入流水线的指令全部执行完成，或允许异常指令之前的所有指令执行完成
  - 精确处理：**提交点技术**
    - 在出现异常时标记，指令执行到 **MEM 段**时触发检测并排空之后的所有指令
    - 这样可以保证异常指令之前的指令执行效果已经保存，之后的所有指令执行效果没有写入寄存器或主存

**第 6 章**（`260515.md`、`260520.md`）
- 重点题目：采用合适的存储芯片形成系统
  - 地址线、数据线如何连接
  - CPU 地址线的低位用于连到存储器的地址输入，**高位用于存储器片选**
  - CPU 的读/写命令控制线连到存储器的对应使能端口
  - 存储器的片选信号：与 CPU 的**访存控制信号**、高位地址线有关
  - 通常需要使用译码器和门电路产生各个芯片的片选信号
  - 存储芯片的选择
    - 系统程序区、库函数和常数区选择 ROM
    - 用户程序区、系统程序**工作**区选择 RAM
    - 注意**尽量匹配地址线和数据线的要求**，其次看是否可以通过存储器字扩展或位扩展实现，最后考虑利用地址线/数据线更大的存储器实现
- 校验：奇偶校验、CRC 校验、海明校验
  - 码距：任意两个编码之间的差异位数；编码系统的码距即为任意两个编码之间的最小码距
  - 具有检出 D 位误码的能力，要求最小码距 L 至少为 **D+1**
  - 能检出 D 位误码，即要求任意一个正确编码在 D 步之内不能变为另一个合法编码
  - 具有纠正 C 位误码的能力，要求最小码距 L 至少为 **2C+1**
  - 按**就近纠错原则**理解，能纠正 C 位误码，即要求两个正确编码在 C 步之内的范围不能有重合
  - 编码纠错理论：最小码距 L，检错能力 D，纠错能力 C，有 $L-1\geq D+C$ 且 $D\geq C$
  - 
  - 奇偶校验
    - 让整个编码中 `1` 的数量为奇数/偶数
    - 只能检出 1 位错误，不能纠正错误
  - **海明码**
    - 编号从 1 开始，第 $2^k$ 位上都是校验位、其余位上是数据位
    - 设 $i=2^{j_1}+2^{j_2}+\cdots$，则第 i 位由第 $2^{j_1}, 2^{j_2}, \cdots$ 位上的校验位共同校验
    - 如何**确定需要几位校验码**？设数据位数 k，校验位数 r，则应满足 $2^r-1\geq k+r$
    - 纠错过程：接收方计算每个校验位与其校验的所有位的**异或和**，按校验位序号拼接，结果即指出错误的位号
    - 标准海明码的最小码距为 **3**，SECDED 海明码的最小码距为 **4**（引入一个全局奇偶校验位）
  - **CRC 校验**
    - 生成多项式最高次数为 k 时（共 k+1 位），则将原数据左移 k 位
    - 将左移后的数据**模 2 除以**生成多项式，每一步只要**当前余数最高位为 1**，部分商就为 1，否则为 0
    - 将最后得到的 k 位余数拼接在左移后原数据的末尾 k 位，即为 CRC 码
    - 纠错过程：将接收到的数据除以生成多项式，按余数进行查表得到出错位
    - 余数与出错位的对应关系只受生成多项式影响，与数据无关
    - 余数循环：对余数末尾补 0 后模 2 除以生成多项式即为下一个余数
    - 根据余数循环，把接收数据循环左移 1 位，同时余数末尾补 0 后模 2 除以生成多项式，直到余数指示最高位出错，此时直接翻转最高位之后再循环左移回到原数据，即可实现**固定位置纠错**
- 提高访存性能：Cache
  - 命中率：与 Cache 容量和块长有关
    - Cache 容量影响**时间局部性**发挥，容量越大，一个 Cache Line 在短时间内被替换的可能性越小
    - 由上述分析可见，容量增大到一定程度后，命中率将不再显著提升
    - 块长影响**空间局部性**发挥，块越大，一个 Cache Line 中数据越多，对相邻数据的缓存规模越大
    - 随着块长增加，命中率将先升后降，**下降原因**：块数减少，可能导致抖动问题
    - 命中率只取决于 Cache 和主存的访问次数之比，和二者的实际访问开销无关
  - 访问效率：Cache 访问时间（可简化理解为**定值**）与**过程中主存的平均访问时间**的比值
  - 映射策略
    - 块号：主存地址中的高位，即为 Tag 段
    - 全相连映射：主存中每个块都可以映射到 Cache 中任意一个块，维护每个 Cache 块上存储的主存块号
    - 直接映射：每个主存块固定映射到某个 Cache 块（单射），在主存块号中切分引入 Index 段作为映射到的 Cache 块号，Tag 段作为校验标记检查是否命中
    - 组相连映射：把 Cache 分为若干组，每个组内有若干 Cache 块
      - **组间直接映射，组内全相连映射**
      - 如果只有 1 组，即退化为全相连映射；如果组内只有 1 个块，即退化为直接映射
      - Index 段用于索引 Cache 组号，Tag 段作为校验标记检查是否命中
      - 组内的块数一般为 2 的幂
      - <strong>（易错）</strong>路数越高，Cache 的组数越少
    - 相连度越高，Cache 的空间利用率越高，同时发生块冲突的概率越低，但同时带来**更大的命中确认开销**和**更复杂的替换算法**
  - <strong>（易错）</strong>不论是主存还是 Cache，地址位数都只取决于其容量，一般来说**每个地址上存放一个字节**
  - **主存地址分区**：块内地址段、Cache 地址段（指示直接映射的块号/组相连的组号）、标记段
    - 块内地址段字长取决于块的大小（几字节？）
    - Cache 地址段字长取决于 Cache 的块数
    - 剩余的高位主存地址段即为标记段
  - 置换策略
    - LFU 算法：选择累计访问次数最少的块替换
    - LRU 算法：选择上一次访问时间最久远的块
    - FIFO 算法：选择当前最早被换入的块
    - 随机算法：随机选择被替换的块
  - 写策略：写命中、写失效
    - 写命中时：写直达/写回
    - 写直达法，写入的数据同时修改 Cache 和主存，写入操作的时间（注意**只是写访存指令执行时间的一部分**）等同于主存访问时间
    - 写回法，写入的数据只修改 Cache，写入操作的时间等同于 Cache 访问时间
    - 写直达法**不涉及换出**，写回法在**对同一变量多次写入**时性能更好
    - 写失效时：按写分配/不按写分配
    - 按写分配，**先把目标块换入 Cache**，再进行写入（是否写入主存取决于采用写直达还是写命中）
    - 不按写分配，直接向主存写入
    - 在写失效时采用什么策略，主要取决于写入的目标数据是否有**读取的时间局部性**
- TLB：了解即可
  - 虚拟存储器
    - 解决物理主存无法满足多用户多任务系统下程序内存需求的问题
    - 程序员按虚地址编程
    - 程序运行时若分配的物理内存不够，则只把当前正在运行或将要运行的程序片段调入主存，其余部分仍然放在辅存中
    - 虚地址范围可以大于实地址范围或小于实地址范围
    - 虚地址范围较小时，访存指令的偏移量字段可以缩短，从而减小整条指令的长度，有利于提升 I-Cache 性能和取指能力（一次可以取出更多指令）
  - 虚存大小仅依赖于辅存的大小
  - 在主存命中率高时，虚存的访问时间接近主存
  - **Cache 与主存构成系统内存，主存和辅存构成虚拟存储器**
  - 引入 TLB 后的虚拟地址映射过程
    - 拿到虚拟地址后，同时访问 TLB（较快）和主存中的页面映射表（较慢）
    - 在 TLB 中虚拟地址作为 **key**，在主存页面映射表中虚拟地址作为**索引**
    - 若 TLB 命中，则可以直接得到物理页号；否则取主存页面映射表的结果
  - TLB 采用**全相连映射**，即一个外存页可以映射到任何空闲的内存页面

- EPROM 的 nPD/Progr 引脚：用于在 ROM 空闲时降低其功耗，或用于向 EPROM 芯片写入数据
- 并行存储
  - 存储体：同一时间只能接收单条访存请求的存储单位
  - 单体多字系统
    - 只有一个存储体，但是一次读出多个字的数据并缓存在寄存器中
    - 适用于顺序访存较频繁的场景
  - 多体并行系统
    - 有多个存储体，可以并行工作
    - 高位交叉编址：地址上紧邻的一部分内存位于同一个存储体内，适用于多个不同程序**对于内存不同位置的访问需求**
    - 高位交叉编址**方便扩容**，直接增加内存条即可
    - 低位交叉编址：地址上紧邻的内存分别位于不同存储体，适用于**单个程序顺序访问内存**
    - 低位交叉编址提高连续访问带宽（M 个存储体的多体系统，带宽是单体系统的 M 倍），在结构上适用于 CPU 的**突发访存**实现
    - 带宽：单位时间内读出数据的数量，例如 MB/s

**第 7 章**：掌握总线仲裁和总线通信的基本方式，了解总线控制器的基本实现（`260522.md`）
- 总线仲裁：对多个主设备提出的总线占用请求进行仲裁
  - 集中式仲裁
    - 由一个单一的总线仲裁器对所有设备的总线占用请求进行仲裁
    - 每个设备模块连**请求线 BR** 到总线仲裁器，并通过**总线授权线 BG** 接收总线占用许可信号
    - 链式查询：所有设备共享一条 BR 线，BG 线按特定的顺序串联各个设备（总线占用的优先级固定）
    - 计数器定时查询：总线仲裁器维护一个定时自增的计数器，把计数值广播给所有设备，若某个设备发出 BR 且计数值与其 ID 匹配，则允许它占用总线
    - 独立请求查询：每个设备使用单独的 BR 和 BG 线连到总线仲裁器，由总线仲裁器中的排队电路决定响应哪个设备的总线请求
    - 独立请求查询是现在普遍采用的集中式仲裁方式
  - 分布式仲裁
    - 自举分布式仲裁
      - 希望占用总线的设备将自己的优先级代码发到仲裁总线上
      - 仲裁总线对所有优先级代码进行线或
      - 如果设备发现总线上的仲裁信号高于自己的优先级，就撤回自己的请求
      - 最终只有最高优先级的设备发现仲裁总线上的最终优先级与自己相同
    - 冲突检测分布式仲裁
      - 设备侦听总线是否空闲，若空闲则立刻发送数据
      - 若有多个设备同时发送了数据，各个设备会侦听到总线上的信号重叠，同时停止发送，并**执行退避算法**在一个随机时间后重新尝试占用总线
    - **并行竞争分布式仲裁**
      - 第一个设备将仲裁号写入总线
      - 每个希望占用总线的设备把自己的仲裁号与仲裁总线上的仲裁号进行比较，若仲裁总线上仲裁号更大，则不再试图覆写仲裁总线上的仲裁号
- 总线操作
  - 读操作：从设备→主设备，总线上按地址—命令—数据的顺序传输内容
  - 写操作：主设备→从设备，总线上按地址—数据—命令的顺序传输内容
  - 猝发式传送：对于固定长度的块的读写，主设备只给出一次块起始地址，之后从设备按顺序一次性写入或读取该块
  - 
  - 写后读：**原子操作**，检测写入操作是否正确完成
  - 读后写：**原子操作**，用于多道程序系统中保护一个共享存储资源
  - 
  - 广播：主设备对多个从设备**同时写入**
  - 广集：主设备从多个从设备**同时读取**
  - 广集利用线或/线与，例如 CPU 可以**一次性获取所有设备的可用状态**，**定位中断源**等
- 总线周期：完成一次总线操作的时间，分为**申请分配—寻址—传送—结束**
- 总线数据传送方式
  - 串行：单条传输线，采用**脉冲传送**（连续传输 1 时能明确计数 1 的数量）
  - 并行：多条传输线，采用**电位传送**（需要依赖一个额外的同步信号确定读取时机）
  - 串行传送可以避免串扰和信号到达时间不一致，适用于**部件间**信号的长距离传输
  - 并行传送一般只用于**芯片内部**的短距离高带宽数据通路
  - 分时复用：同一条总线在不同时刻承担不同类型数据的传输工作（例如数据和地址）
  - 分时复用可以**节约芯片引脚数量**
- 总线通信方式
  - 同步通信：适用于总线长度较短、各部件存取时间一致的场合
    - 各个部件可以有自己的时序发生器（提高部件内部的精细操作效率），但**这些时序信号必须与总线控制部件发出的时钟信号保持同步**
    - 时钟信号到达各个部件可能存在微小时间偏差，不适合长距离通信
    - 时钟信号必须满足速度最慢的设备的要求
  - 异步通信：不要求所有部件统一操作时间，且允许各个部件的速度不同
    - 采用应答方式，需要在主从设备间增加两条应答线
    - 不互锁：主从设备向对方发出信号一段时间后自动撤销
    - 不互锁适用于速度相近、可靠度高的**内部组件间通信**
    - 半互锁：主设备的请求直到接收到从设备的回答后才撤销，从设备的回答经过一段时间自动撤销
    - 半互锁适用于多个主设备访问一个**共享存储器**
    - 全互锁：从设备的回答直到主设备的请求被撤销之后才撤销
    - 全互锁适用于网络通信、**速度差异大**的异步外设接口
- 异步串行通信
  - **起始位固定为 0**，**停止位固定为 1**
  - 数据**从低位到高位**依次传送
  - 比特率：单位时间内传送的**有效**数据位数
  - 波特率：单位时间内传送的**总**数据位数
  - 比特率和波特率的单位都是 bps(bits per second)
- 同步通信
  - 在正式数据开始之前，使用**两个同步字符**指明数据传输开始（建立起同步、锁定字符边界、避免线路噪声误判）
  - 正式数据连续传送，不再对单个字符使用附加位（起始位、终止位）
- 半同步通信
  - 所有信号的传递都在时钟沿上
  - 若从设备尚未完成对当前信号的响应，则**将等待信号置为有效**，此时主设备将插入若干等待周期，期间保持原有传输的信号（地址、命令等）不变
  - 各个模块仍然由统一时钟控制，可靠性强；但等待时间不确定，工作效率较低
  - 适用于**工作速度差异较大**的各个组件组成的系统
- 分离式通信方式：把一个总线周期分为两个子周期
  - 主设备向从设备发送地址、命令、写入数据后释放总线
  - 从设备准备好数据后请求占用总线，向主设备发送数据
  - 每个设备都是主设备
  - **设备准备数据期间不占用总线**，保证总线被占用期间都在有效工作，没有空闲等待时间
  - **控制逻辑较复杂**，多见于大型计算机系统

**第 8 章**：I/O 信息交换方式，I/O 通道与 DMA 控制器的硬件实现（`260527.md`）
- I/O 信息交换方式
  - 程序查询方式：有 I/O 请求时，CPU 修改 I/O 接口的控制寄存器，之后不断**忙等—执行数据传送**
  - 程序中断方式
  - DMA 方式
    - CPU 在主存中开辟连续地址的缓冲区，用于暂存将要接收或发送的数据
    - CPU 向 DMA 控制器写入控制信息：目标 I/O 设备、主存缓冲区首地址、传输数据量、传输方向等
    - DMA 控制器在 I/O 设备就绪后请求总线占用，之后在主存和 I/O 设备间通过总线流动，**不经过 CPU**
    - 传输完成后，DMA 控制器向 CPU 发出中断，由 CPU 执行中断服务程序，确认数据传输过程正确完成
    - DMA 控制器只负责数据传送工作
    - 
    - DMA 停止 CPU 访问内存：DMA 在工作时 CPU 完全无法访问主存
    - 周期挪用/周期窃取：I/O 设备有传输需求时，DMA 向 CPU 窃取少量主存周期
    - 周期挪用适用于 **I/O 读写周期大于主存周期**的情况
    - DMA 与 CPU 交替访存：把 CPU 周期分为专供 CPU 访存和 DMA 访存的两部分
    - 交替访存要求主存周期至多是 CPU 周期的一半，通常适用于**主存速度远高于 CPU 速度**的系统
    - 
    - DMA 控制器的结构：内存地址寄存器、字计数器、数据缓冲寄存器、设备地址寄存器
    - 字计数器通常初始化为**字数的补码负数**，每传送一个字，计数器自增，直到其溢出时向中断机构发出溢出信号，表明数据传输完成
    - 内存地址寄存器维护**下一个将要进行数据交换的内存地址**
    - DMA 传送的过程：预处理—数据传送—后处理
    - 预处理阶段，CPU 向 DMA 写入本次传输的各种参数
    - 后处理阶段，CPU 校验主存中数据是否正确，决定是否继续使用 DMA（所需的数据是否已经全部传输完成，是否需要切换物理页继续填充，流式场景下是否需要切换另一个 buffer 填充新数据；传输过程是否发生硬件错误）
  - 通道方式
    - 通道有自己的控制逻辑，可以执行少量针对 I/O 的有限指令集
    - 常见的带有通道的 I/O 系统控制轴：主机—通道—设备控制器—I/O 设备
    - 设备控制器负责将抽象的命令转化为物理设备的实际动作（如移动磁头），缓存数据，监控设备状态，校验数据
    - 通道的功能：执行 CPU 的 I/O 指令，从内存中读取通道指令并执行，在外设与内存之间进行数据传送，在内存中保存外设和通道的状态信息，按顺序向 CPU 发出外设中断请求和通道中断请求
  - 几种信息交换方式主要差异体现在 **I/O 设备与 CPU 的连接和控制方式**上
- 磁记录原理与记录方式
  - 写入：记录介质匀速通过磁头，磁头中通入一定方向的电流，使介质局部形成磁化单元，根据磁化方向不同规定为“0”位和“1”位
  - 读出：记录介质的读出线圈感应磁化方向的变化，产生感应电压，由此读出该位上的数据
  - **磁记录方式**![各种磁记录方式的写电流波形示意](attachments/pic-260527-4.png)
    - 归零制 RZ：正脉冲为 1，负脉冲为 0；在记录下一位信息前**电流归零**；有自同步能力
    - 不归零制 NRZ：**写入时**磁头线圈始终有电流，电流方向在 0/1 或 1/0 翻转时切换；无自同步能力
    - 见 1 翻转的不归零制 NRZ1：在记录 1 时电流方向切换，记录 0 时不切换；无自同步能力
    - 调相制 PM：单个周期内，记录 0 时电流方向由负变正，记录 1 时电流方向由正变负；有自同步能力
    - 调频制 FM：“1”位数据频率是“0”的两倍，**在所有位边界上翻转一次**；有自同步能力
    - 改进调频制 MFM：**连续出现两个及以上的“0”时，在位边界上翻转一次**；有自同步能力
    - 编码效率：记录单位数据时，磁头电流方向可能出现的**最大翻转次数**（计入单边时钟上升沿处的翻转情况）
- 磁盘的不同编码形式

**第 9 章**（`260529.md`）
- 循环级并行如何提升性能？
  - 定点/浮点指令的并行
    - 将定点与浮点指令尽可能放在相邻的指令执行
    - 注意结合每条指令的 use 延迟要求（某条指令的执行结果要在几个周期后才可用）合理安排各条指令的位置
  - 循环展开，寄存器重命名、指令调度
    - 循环内调度：在同一个循环内的指令中进行调度，例如分支延迟槽、定点浮点并行
    - 
    - 循环间调度：将原有的多轮循环整合为一轮
    - 具体整合几轮循环，需要取决于循环次数的倍数特征
    - 减少循环变量的修改、分支条件的判定等指令（但要注意**立即数偏移量的修改**）
    - 当循环长度过小、循环内计算得出的数据尚未被复用时，**寄存器需要重命名**以避免发生数据冲突
    - 循环间调度+循环内调度：在循环间重排指令，运用不同循环的指令充分填补延迟槽
    - 常见的做法：在寄存器改名的情况下，**把多轮循环中的同一条指令集合在一起执行**
  - 超标量、超长指令字
    - 超标量：每个时钟周期同时执行一条整型指令和一条浮点（运算）指令
    - 需要扩展寄存器端口：整型指令中包括浮点 Load 指令
    - 当整型指令发生停顿时，即使浮点指令不需要停顿，也必须连带卡在同一个寄存器段
    - 如果整型指令不停顿、浮点指令停顿，对下一对整型-浮点有两种方案：阻碍下一对指令进入流水线，或让下一条整型指令与当前浮点指令配对向下流动（“滑动”）
    - 仍然需要注意**浮点 Load/Store 指令与浮点 ALU 指令之间的数据依赖关系**，据此安排浮点指令进入浮点流水线的合适时机
    - 
    - 超长指令字
    - 由编译器识别无关指令，将它们拼接成一个超长指令字
    - 如果没有足够的指令可以用于拼接成一个超长指令字，必须在空出的位置填入空指令
    - 在并行度变动较大的程序上性能极其受限（插入了大量空指令）
    - 在硬件层面没有任何优化动作（CPU 将完全按照输入的指令顺序执行），因此需要编译器完成分支延迟消除的工作
    - 需要更多套硬件以支持并行，同时需要注意指令之间的数据依赖
    - 
    - 循环间相关：下一轮循环靠近开头的指令会使用上一轮循环靠近结尾指令的运行结果
    - 循环间依赖转循环内依赖![循环间依赖转循环内依赖示意](attachments/pic-260610-2.png)
    - 将原有的循环间依赖通过调整指令顺序、**增加序言和收尾指令**转为循环内依赖，避免形成循环迭代之间的链式依赖关系
    - 在超标量优化下，有利于**实现不同循环迭代之间的并行**

**第 12 章**
- 目标算法分析
  - 计算特征（重复的计算方式，矩阵×向量，向量+向量），访存特征（局部性特征，数据复用的距离）
  - 计算和访存的关系（带宽需求，访存一次够执行几次计算）
- 处理器结构
  - 指令集设计：运算类、访存类、控制类
  - 硬件加速器：部件设计（乘加单元 MAC）、流水化（定点指令、浮点指令）
  - 标量 MAC：一个时钟周期内只能接收一对数据，加到给定的寄存器上
  - 向量 MAC：一个时钟周期内可以接收一对向量，各分量分别相加（内积）后加到给定的寄存器上
  - 向量 MAC 需要使用加法树，通过使用并行乘法器**理论上可以在一个时钟周期内完成计算**
- 设计的方法是相似的，但应用的场景变为专用
- 性能评价指标：TOPS、访存带宽
