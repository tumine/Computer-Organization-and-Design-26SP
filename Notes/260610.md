### 课程回顾
**第 1 章**：了解计算机系统构成，熟悉计算机系统性能评估方法
- 性能评估方法：芯片成本计算、CPU 时间、Amdahl 定律（加速效果）
  - CPU 时间：程序执行的总周期数 $\text{CLK}$，计算机工作的时钟频率 $f$，$T_{\text{CPU}}=\frac{\text{CLK}}{f}$
  - **响应时间**：事件开始到结束的时间；用户标准
  - **吞吐率**：单位时间内能完成的工作量；多道程序系统视角
  - 性能比较：“X 比 Y 快”指的是 Y 的响应时间比 X 长（可以进一步量化），或者 X 的性能比 Y 好（性能与响应时间成反比）
  - 可靠性：平均无故障运行时间 **MTBF**
  - 可用率：平均修复时间 MTTR，可用率记为 **MTBF/(MTBF+MTTR)**
- 计算机的层次
  - 应用语言→高级语言→汇编语言→操作系统→机器语言→微指令系统
  - **每条机器码执行一个微程序**，每条微指令在一个时钟周期内指示某个功能部件完成一个原子硬件操作
  - 操作系统为汇编语言/高级语言提供其执行过程中使用的**基本操作的具体实现**，并管理计算机软硬件资源
- 计算机处理一条指令的过程
  - 例如，处理一条输出字符串指令的过程
  - 如何串联各个组件？CPU、主存、磁盘、显示器
  - 冯·诺依曼架构的特点：五大功能组件，指令和信息如何表示，...
- CPU 发展趋势：核集成度→频率扩增→核扩增
  - CPU 发展过程中遇到哪些墙？处理和解决的思路是什么？
  - 存储墙与 I/O 墙：利用程序的时空局部性原理，引入存储器层次结构、访存 burst 技术、RAID 技术
  - 频率墙与线延迟墙：通过指令级并行增加在一个时钟周期内能完成的工作量，从而提高性能，引入流水线、超标量、超长指令字、乱序多发射等技术
- **Amdahl 定律**：加速的成本是什么？加速带来的效益是否足以覆盖成本？
  - 可改进比例 $f_e$，部件加速比 $S_e$，$S=\dfrac{1}{(1-f_e)+\frac{f_e}{S_e}}$
  - Amdahl 定律固定工作量来计算加速比，是一个悲观结果；Gustafson 定律提出固定并行计算时间来计算加速比，得到乐观结果
  - Gustafson 定律：性能与核心数成正比
- CPU 性能公式：$T_{\text{CPU}}=\text{CPI}\times \text{IC}\times T_{\text{CLK}}$，如何从三个参数入手分别进行优化？
  - 程序总指令数 $\text{IC}$，$\text{CPI}=\frac{\text{CLK}}{\text{IC}}$

- 冯诺依曼结构与哈佛结构的主要区别
  - 指令、数据是否分离存储
  - 是否对指令、数据存储使用两条独立总线，两条总线之间毫无关联
- 运算器最少需要包括三个寄存器：累加器 ACC、乘商寄存器 MQ、操作数寄存器 X
- 控制器的三个关键组件
  - 程序计数器 PC：当前执行的指令地址，取指后可以自动指向当前指令的后继
  - 指令寄存器 IR：当前执行的指令内容
  - 控制单元 CU：根据当前指令内容，发出各种控制信号和微操作命令序列，控制计算机其它部件的工作
- 存储器：存储体、各种逻辑部件和控制电路
  - **存储元件→存储单元→存储体**
  - 一个存储元件可以存储一个二进制位，例如一个触发器
  - 一个存储单元通常可以存储一串二进制数，称为一个**存储字**，这串数的二进制长度称为**存储字长**
  - 注意**存储字与 CPU 采用的机器字并不一定相同**：存储器按字节寻址，则一个存储字即为一个字节；存储器按字寻址，则一个存储字即为一个机器字
  - 存储地址按存储单元进行编号
  - MAR、MDR：分别存储访存过程使用的地址和数据；MAR 的字长等于存储地址的位数，MDR 的字长等于存储字长
  - （题型）如何**由 MAR、MDR 推出存储单元数、存储容量**？

- 指令格式：操作码+地址码，地址码指定操作数的存储位置

**第 4 章**：设计并实现流水化的处理器（数据通路、控制信号、状态机），进行流水线性能评估，掌握各种相关的产生原因、解决方法（`260415.md`
- 流水线：在多周期的基础上，充分利用空闲的部件
- 流水线的性能评价：吞吐率、加速比、效率
  - 流水线不能缩短单个任务的执行时间，但可以提高吞吐率
  - 吞吐率 TP：单位时间内流水线完成任务的数量。在任务数极多的情况下，吞吐率趋近于流水线时间 $\Delta t_0$ 的倒数
    - 各个流水段时间不等时，理论最大吞吐率即为**最大流水段时间的倒数**
    - 计算实际任务完成时间，主要关注**每个任务流出流水线的时刻**；第一个任务走过完整的流水线，接下来每隔 $\Delta t_0$ 都会有一个任务流出
    - 流水段时间不等时，任务流入、流出的瓶颈都在于时间最长的流水段；可以画出一个实际例子辅助理解
  - 加速比 S：完成相同任务，非流水线执行与流水线执行的时间之比；理论最大加速比即为流水段数量（流水线稳定时）
  - 效率 E：实际加速比与最大加速比的比值，或执行完 n 个任务所需的**理想时间**（$n\cdot \Delta t_0$，因为流水线稳定后，每隔 $\Delta t_0$ 就会有一个任务完成）**与实际时间的比值**
    - 也可以理解为在时空图上执行 n 个任务占用的时空区域与相同时间内全部时空区域的面积比
    - 在 $\Delta t_0$ 不变的前提下，效率与吞吐率成正比
  - 提高吞吐率：细化流水段以压缩时钟周期，均衡流水段延迟，多发射流水线
  - 提高加速比：增加流水级数，引入分支预测，引入数据前递
  - 提高效率：增加任务数，采用非线性流水线，采用哈佛结构
- 结构相关：硬件资源不足
  - 通过引入**哈佛结构**来解决，指令和数据存储分离
- 为什么产生了数据相关？数据依赖
  - 旁路技术（判断、传送）
    - 分为 `EX/MEM → ID/EX` 前递、`MEM/WB → ID/EX` 前递
    - 对于 Load-Store 指令子序列，可以增加 `MEM/WB → EX/MEM` 前递路径来消除流水线停顿，但要考虑成本和性能权衡
  - 互锁（识别、停顿）
    - 读访存指令在 MEM 段结束后才拿到数据，下一条指令执行到 ID 段时发现数据相关，停顿一个时钟周期
    - 停顿的具体实现：当前时钟周期把下一个段（EX 段）的段间寄存器清零；**阻止 PC 自增和 IF/ID 段间写入**
- 控制相关：分支指令
  - 如何降低分支指令带来的开销：判断过程放到 `ID` 段，这一段实际执行的工作不多，有时序余量
    - 延迟分支：从前调度（从**分支指令之前**找一条不影响分支运行结果的指令，让它在分支指令之后运行）、从失败处调度、从目标处调度
    - 分支预测
      - 静态：认为向**后**转移 taken，向**前**转移 not taken；有利于循环执行过程中减少停顿
      - 动态：建立转移预测缓冲器，对每条分支指令根据其以前的跳转状态预测或更新状态位
      - 2 位动态预测器有两种实现方式，取决于切换预测结果时预测倾向是强（第一次预测错误时保持当前倾向不变）还是弱（第一次预测错误后立即切换预测倾向）
    - 不同的预测方法带来不同的预测精度
- 目标：让 CPI 尽可能靠近 1
- 让 $\text{CPI}<1$：超标量、超流水线、超长指令字
  - 额外的硬件资源需求
- 
- RISC-V 适于流水线的特点
  - 指令字定长
  - 每种指令的**操作数位置固定**，因此可以在 ID 段直接取操作数
  - **只有 Load/Store 访存**，这样不会出现“计算访存地址-访存-结果参与运算”这一个无法被其它类型指令复用的流水片段，缩减了流水线段数
  - 操作数在内存中**强制字对齐**，保证一次访存就可以取出操作数
- MIPS 与 RISC-V 数据通路的区别
  - 段间寄存器中和分支目标计算的基址是 PC（RISC-V）还是 PC+4（MIPS）
  - 源、目标寄存器编号的生成是否需要通过 MUX（这些寄存器在指令中的编码位置是否固定）
  - 立即数生成是否需要专用生成器
- 解决冒险的方法
  - 硬件：在指令运行时**动态**检测数据依赖
  - 软件：编译器运行时**静态**检测数据依赖；处理器之间的兼容性差

**第 5 章**：中断、异常本质上是 CPU 的功能扩展（`260506.md`、`260513.md`）
- 中断分类：软中断、硬中断
  - 软中断：由执行特定的指令触发，例如程序异常，断点；如果重新执行这个指令片段，**仍然会在相同的位置触发相同的中断**
  - 硬中断：与 CPU 当前执行的指令没有关系
    - 可屏蔽中断：一般的 I/O 设备发出的中断，可以不立刻处理
    - 不可屏蔽中断：发生严重硬件级错误时发出的中断，必须立刻处理
- 中断管理需要解决的问题
- 中断机构：软硬件协同逻辑
  - IF@PSW：位于程序状态字中，指示是否屏蔽外部所有可屏蔽中断；**架构特异性**
  - 中断请求标记 INTR：每个中断请求源对应一个 INTR 触发器
    - 分散布局：分布在各个中断源接口电路中
    - 集中布局：位于 CPU 中断系统内
  - INTA：CPU 响应中断的信号，用于冻结中断控制器状态，从中断控制器获取中断类型
  - 中断判优
    - 软件实现：通过一系列分支结构查询指令选定一个优先级最高的中断
    - 软件实现易于动态改变优先级，但中断判优过程开销较高
    - 硬件实现：链式排队器，关键在于**运用与非门**处理获得给下一个中断源的中断允许信号 INTP 输出
    - 排队器并行实现时判优效率高，串行实现时易扩展
  - 中断响应
    - 条件：CPU 允许中断触发器 EINT=1
    - 时机：在**单周期/多周期 CPU** 上，一条指令执行结束，CPU 发出中断查询信号
    - 中断隐指令：保护程序断点（PC 信息），寻找中断服务程序入口地址，禁用中断（不论是否允许嵌套中断，**至少在进入中断服务程序之前**）
  - 保护现场
    - 保存断点：由中断隐指令执行
    - 保存寄存器的值：由中断服务程序执行
    - 中断服务程序的结构：保护现场—执行真正的中断服务程序—恢复现场—中断返回
  - 寻找中断服务程序入口地址
    - 硬件向量法：由排队器选出优先级最高的中断，送入中断向量形成部件生成向量地址
    - 软件查询法：由 CPU 执行一系列中断查询指令找出优先级最高的中断，再执行查表指令找到该设备对应内存单元
    - 硬件向量法生成向量地址后，用该地址覆写 PC，下一步执行该地址上的 JMP 指令
    - 软件查询法先把内存单元上的地址数据加载到寄存器中，再执行一条间接跳转指令跳转到中断服务程序入口地址
    - 两种方法下内存单元中存储的内容完全可以互换，**并不与寻找入口地址的方法绑定**
  - 多重中断：允许中断打断中断
    - 提前设置开中断，在中断隐指令完成保存现场后、中断服务程序开始之前就打开中断
    - 优先级高的中断源可以打断优先级低的中断执行
    - 屏蔽：禁用低优先级的中断
    - 需要在硬件排队器的与非门上添加一个屏蔽位输入，所有屏蔽位组合形成屏蔽字，屏蔽字随着当前执行中断的优先级而不断动态改变
    - 新屏蔽字的设置需要在保存现场之后，以**保存原有屏蔽字和寄存器**，避免设置屏蔽字的过程覆写寄存器；老屏蔽字的恢复需要在恢复现场之后
    - 屏蔽可以改变处理优先级（软件逻辑，中断服务程序），但不能改变中断响应优先级（硬件逻辑，中断隐指令）
- 记录异常指令、异常信息：EPC 指向处理完异常后应当执行的**下一条正常指令**
- 算术溢出、异常指令的检测分别位于哪个周期？
  - 异常指令检测在 ID 段查出，在 EX 段开始执行异常处理
  - 算术溢出检测在 EX 段查出，在 MEM 段开始执行异常处理
- 
- 流水线异常处理
  - 非精确处理：允许已进入流水线的指令全部执行完成，或允许异常指令之前的所有指令执行完成
  - 精确处理：**提交点技术**
    - 在出现异常时标记，指令执行到 **MEM 段**时触发检测并排空之后的所有指令
    - 这样可以保证异常指令之前的指令执行效果已经保存，之后的所有指令执行效果没有写入寄存器或主存
