根据两种 RAM 的性能特点，Cache 使用 SRAM（集成度低，速度快，不需要刷新），DDR 使用 DRAM（集成度高，速度慢，需要刷新）

程序运行过程中，任何时刻只使用一小部分的数据；这使得较小的 Cache 可以支撑大规模的程序运行

程序的局部性原理
- 时间局部性：当前用的数据在最近的将来很有可能还会使用（循环）
- 空间局部性：下一时刻用的数据很有可能在当前用的数据位置附近

理论上，运算过程的所有实现细节方案都可以实现；**区别在于方案的优劣**

DMA(Direct Memory Access) 技术使得外存、外设与内存之间的数据交互过程不需要 CPU 的干预

冯·诺依曼架构（普林斯顿架构）以运算器为中心；现代计算机技术以内存为中心
- 为什么早期架构以运算器为中心？所有指令都要到 CPU 中进行运算
- 哈佛结构：指令和数据分开存储，分别使用一条独立总线
  - 一个时钟周期里，普林斯顿架构只能取指/取数，哈佛架构可以同时做到取指/取数
  - 哈佛架构的缺点在于并行：需要提供的总线带宽和硬件资源更多

一个运算器至少需要 3 个寄存器：累加器（ACC）、乘商寄存器（MQ）、操作数寄存器（X）

译码的逻辑在 Verilog 中使用 `case` 语句实现

在内存模块外需要有一个内存控制器
- 与 CPU 的 MAR/MDR 交互
- 实现在一个时钟周期内拼接多个内存地址上的数据

计算机体系结构&计算机组成
- 相同的体系结构可以有不同的组成（功能一样，但是具体的实现不一样）
- 体系结构：计算机有什么功能？组成：这些功能如何实现？
  - 例如，计算机有哪些指令，属于体系结构的问题；这些指令如何实现，属于组成的问题

## 硬件性能指标
MAR 的位数反映存储单元个数，MDR 的位数反映存储字长

三种字长的概念
- 机器字长：CPU 内部寄存器的宽度
- 存储字长：内存内部一个内存单元的宽度
- 数据字长：总线的宽度

现实的问题：CPU、内存、总线的厂商不同，有时难以做到三种字长统一？
- 经常遇到的问题：算力、内存充足，但总线很慢（**带宽不够**），CPU 被迫空转
- 总线太宽，机器字长太小，就会导致数据在 CPU 中堆积
