## 任务分析与难度评估

### 任务一：指令集扩展（M）(15分)
- **工作量**：中等。需要增加乘除法器模块，并在译码阶段、执行阶段扩展对 RV32M 指令（`mul`, `mulh`, `mulhu`, `div`, `divu`, `rem`, `remu`）的支持。
- **实现难度**：较高。难点在于不能使用原生 `*`、`/`、`%` 运算符或 IP 核，需自行实现硬件乘除法器，且乘法需在 5 个周期内完成（不能用简单的循环加法，可能需要实现 Booth 乘法器或华莱士树）。除法器可能需要实现不恢复余数法（SRT等）。
- **兼容成本**：较低。乘除法器可作为 EX 阶段的独立功能单元接入，只需要在 EX 阶段增加数个周期的停顿（stall）信号，暂停流水线，直至乘除法完成。

### 任务二：指令集扩展（F）(18分)
- **工作量**：较大。需要增加浮点寄存器堆，并在流水线中增加浮点运算模块支持 `fadd.s`, `fsub.s`, `fcvt.s.w`, `fcvt.w.s`。因为需要自己编写测试汇编，可能还需要实现 `flw` 和 `fsw`。
- **实现难度**：高。难点在于自行实现 IEEE 754 单精度浮点数的加减法，需要处理对阶、尾数求和、规格化、舍入等复杂逻辑；整数与浮点数之间的格式转换也包含较多细节。同时不能使用 IP 核。
- **兼容成本**：中等。需要增加独立的浮点寄存器堆，并处理浮点指令和整数指令之间可能的数据相关（尤其是格式转换相关指令）。

### 任务三：Cache 集成 (35分)
- **工作量**：中等。主要工作是将 Lab5 中已完成的 D-Cache 接入到 Lab4 的五级流水线 CPU 的 MEM 阶段。
- **实现难度**：中等。既然 Lab5 已完成 Cache 设计和测试，主要难点在于 CPU 与 Cache 的握手协议。由于 PDU 框架的内存原本是 0 延迟，现在引入 Cache 的 miss 延迟，需要修改框架代码引入读写延迟（模拟 DRAM），并在 CPU 的 MEM 阶段实现基于 Cache Hit/Miss 的停顿机制。
- **兼容成本**：较高。Lab4 的 CPU 原本假设 MEM 阶段总是 1 周期完成。接入 Cache 后产生不定周期的停顿，需要仔细修改 PC、IF/ID、ID/EX、EX/MEM 等所有段间寄存器的使能端，确保在 Cache Miss 时冻结整个流水线状态。

### 任务四：分支预测 (32分)
- **工作量**：大。需要同时实现局部历史分支预测（BHT+PHT）和全局历史分支预测，并设计竞争算法。
- **实现难度**：高。难点不仅在于预测器逻辑本身（状态机的维护、全局历史寄存器的更新），更在于预测错误时（Mispredict）流水线的状态恢复机制。需要判断并区分预测成功、预测跳转但实际未跳转、预测不跳转但实际跳转等多种情况，并正确清空指令。
- **兼容成本**：较高。深度切入流水线的 IF 和 ID/EX 阶段。需要改变原有的跳转判断逻辑：Lab4 原本可能在 EX 段计算分支结果并冲刷流水线，而分支预测在 IF 段给出预测 PC，如果 EX 段发现预测错误，需要恢复正确的 PC 并冲刷在此期间预测错误取出的指令。

## 较优实现路径（满分 100 分策略）

**Lab6 评分规则**：
- 完成 1 个任务：直接得该任务分数。
- 完成 2 个任务：最高分×2 + 最低分。
- 完成 3 个任务及以上：固定 100 分。

### 推荐路径：任务三 (Cache) + 任务四 (分支预测)
**得分计算**：`35 * 2 + 32 = 102`，最后得 100 分满分。

**选择理由**：
1. **性价比高**：虽然任务三和任务四看似大部头，但可以通过完成 2 个任务就拿到满分。如果选择任务一和任务二，就算做了三个任务（如 M+F+Cache），工作量会极为繁重，尤其是手写并调试硬件乘除法和浮点运算。
2. **复用前期成果**：Lab5 已经完成了 Cache 的设计和测试，任务三的核心在于接入和流水线停顿控制。而流水线停顿控制（Stall）实际上是流水线 CPU 的基础技能（在此前处理 Load-Use 相关时可能已有经验）。
3. **结构清晰**：任务三作用于 MEM 阶段，任务四主要作用于 IF、EX 阶段，两个模块之间相对独立，耦合度相对较低，便于分阶段调试。

**实施步骤**：
1. **阶段一：接入 Cache（任务三）**。首先修改存储器接口，让 CPU 支持不定周期延迟，接入 Lab5 的 Cache。调试确保流水线能在 Cache Miss 时正确暂停和恢复。
2. **阶段二：局部历史分支预测（任务四）**。在 Cache 版本稳定后，加入局部历史分支预测器，修改 EX 阶段对预测结果的检验和流水线冲刷恢复逻辑。
3. **阶段三：全局与竞争预测（任务四）**。在局部预测稳定的基础上加入全局预测和冲突解决逻辑。
4. **阶段四：上板验证与报告**。确保在 6 月 3 日前（首要截止日期）完成检查，避免因延期带来的硬性分数扣除。
