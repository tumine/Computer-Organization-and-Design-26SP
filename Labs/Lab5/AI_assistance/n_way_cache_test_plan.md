# N路组相联Cache测试方案

## 参数调节指南

为了测试组相联Cache，我们需要关注 `generate_tb.py` 中的以下几个核心参数：

1. **`WAY_NUM` (路数)**
   - 含义：组相联的路数，即每个由于 Index 映射到的组中，包含多少个 Cache line。
   - 调节方法：对于 N=2, 4, 8, 16 的 N路组相联 Cache，只需将 `WAY_NUM` 分别设置为 2, 4, 8, 16。

2. **`MEM_ADDR_WIDTH` (主存地址位宽)**
   - 含义：决定了主存的总大小。主存包含的总字数为 $2^{\text{MEM\_ADDR\_WIDTH}}$。
   - 调节方法：为了保证主存远大于 Cache，需要保证主存总量远大于 Cache 总量。
     - Cache 容量（字）= $\text{WAY\_NUM} \times 2^{\text{INDEX\_WIDTH}} \times 2^{\text{LINE\_OFFSET\_WIDTH}}$。
     - 默认情况下：`INDEX_WIDTH = 3` (8个组), `LINE_OFFSET_WIDTH = 2` (每行4个字)。如果设置为 16路，则 Cache 容量为 $16 \times 8 \times 4 = 512$ 字。
     - 为保证主存远大于 Cache（例如是其 16 倍以上），主存至少需要 8192 字。因此，测试 16路 Cache 时，建议将 `MEM_ADDR_WIDTH` 至少设置为 **13**（$2^{13} = 8192$）或 14（16384）。

---

## 充分测试方案步骤

为了对您设计的 N路组相联 Cache 进行全面的正确性测试，建议按照以下步骤分别修改参数并运行仿真（可以通过比较 `cache_tb` 运行期间是否有报错来验证 Cache 的正确性和考察未命中率）：

### 步骤 1：功能正确性基准测试（随机读写模式）
首先在随机内存访问模式下验证基础读写、替换策略（LRU/LFU/FIFO 或 Random）和脏块写回功能是否正常。

* **参数配置**：
  * `MODE = 0` (完全随机读写)
  * `WAY_NUM` 分别取 2, 4, 8, 16 进行四轮生成与仿真。
  * `MEM_ADDR_WIDTH = 13` 或更大 (保证主存充足)
  * `READ_NUM = 2000`, `WRITE_NUM = 1000`

### 步骤 2：分支局部性测试（伪顺序访问模式）
利用空间局部性和轻度的跳转，测试缓存对于连续数据访问和组相联结构对于冲突的减缓能力。随着路数的增加，这部分测试的 Miss Rate 应该有明显的降低。

* **参数配置**：
  * `MODE = 1` (带部分随机跳转的顺序读写)
  * `BranchP = 0.1` (10%的跳转概率)
  * `WAY_NUM` 分别取 2, 4, 8, 16 以及对比组 1
  * `MEM_ADDR_WIDTH = 13`

### 步骤 3：压力命中/冲突测试
通过设置极大的主存和较高的读写次数，并且强行减少 Cache 组数（Index 数），从而刻意提高同一个组内的映射冲突概率，着重考察您的 Cache 行替换算法是否高效及正确。

* **参数配置**：
  * `MODE = 0` 或者 `MODE = 1`（带更大 BranchP 比如 0.2）
  * `INDEX_WIDTH = 1` 或者 `2` (将组数压低，刻意制造高冲突)
  * `WAY_NUM = 4` 或是 `8`
  * `READ_NUM = 5000`, `WRITE_NUM = 5000` (提高测试量保障覆盖各种替换边界)
  * `MEM_ADDR_WIDTH = 14`

### 测试执行流程：
1. 按照上文所述在 `generate_tb.py` 中修改参数。
2. 运行 `python generate_tb.py` 生成新的 `cache_tb.v` 和 `mem_bram.v`。
3. 在 Vivado 中将仿真顶层设定为 `cache_tb`，或者通过脚本编译并运行仿真程序。
4. 观察仿真终端打印输出，若没有任何 `Read error ...` 的报错提示并且跑完设定次数，且仿真正常停止，则说明您的 Cache 数据读写及状态机切换正确！
